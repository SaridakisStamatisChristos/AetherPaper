## What is built

- `rig.py`: hierarchical named bones, rigid two-bone IK, procedural limbs/gait, seek-safe spring smoothing, customizable humanoid anchors and pose blending.
- `physics.py`: event-based prop pickup/carry/place/release, analytic falls, damped bounce, spring motion, rope geometry, collision checks.
- `styles.py`: paper cut/scrapbook/storybook style presets, soft contact shadow, backgrounds and transitions.
- `model.py` + `timeline.py`: versioned 0.1/0.2 input contracts, scene actions, camera tracking, look, mouth cues, strict parameter validation.
- `assets.py` + `qa.py`: local asset preflight and hash manifest, ffprobe real media inspection, three decoded representative frames.
- `renderer.py`: streaming offline Pillow RGB frames -> FFmpeg H.264 -> optional external narration WAV/eSpeak -> AAC.
- `cli.py`: `validate`, `manifest`, `snapshot`, `render`, `qa`.

## Reproducibility

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pytest -q
aetherpaper validate examples/rig_demo.json
aetherpaper render examples/rig_demo.json --width 320 --height 180 --fps 12 --out output/rig_demo.mp4
aetherpaper render examples/explainer_demo.json --voice espeak --width 320 --height 180 --fps 12 --out output/explainer_demo.mp4
aetherpaper qa output/explainer_demo.mp4 --frames-dir output/qa
```

## Unsupported and next phase

Current rigs still assume baseline humanoid pelvis/torso/neck drawing; importing arbitrary photo sprites and deformable skinning requires a separate character asset engine. Collision primitives do not implement general rigid-body collision response. Spring and rope animations are time-analytic, not full cloth/fluid dynamics. Mouth cues are user-timed, not automatically derived phonemes. Production-style art direction is not equivalent to procedural functional verification. Cross-repo AetherMotion/ClaudeCreate/AetherRendering compatibility requires integration tests with those repositories; no cross-repo edits made.
