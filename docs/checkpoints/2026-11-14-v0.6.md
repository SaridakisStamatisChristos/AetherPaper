## Motivation and architecture

The v0.5 rendered contact sheet exposed persistent visual-quality limits in the 20-layer skeletal-cutout example: straight-line limbs, awkward silhouette changes, and mechanical transitions. The new system adds an **independent opt-in full-body illustrated pose renderer**, not a destructive rewrite of the successful v0.5 runtime.

The v0.6 branch implements:
- `src/aetherpaper/pose_atlas.py`: seek-safe full-body PNG cel selection from any regular illustration grid, optional quick crossfade, ground/pivot anchoring, configurable image-to-screen size, and manually annotated hand coordinates.
- `src/aetherpaper/posekit.py`: offline-compatible generation of an original fallback six-pose 3×2 transparent atlas from the v0.5 studio kit. This is intentionally a reproducible technical fixture, **not professional artwork**.
- `src/aetherpaper/model.py`: strict v0.6 `visual.type=pose_atlas` validation with 1..64 cells, named poses and 1..500 time-ordered pose switches.
- `src/aetherpaper/paint.py`, `assets.py`: runtime painter integration and local image audit, checksum, path traversal and missing-image checks.
- `src/aetherpaper/cli.py`: `aetherpaper posekit` command.
- `examples/illustrated_poses_v06.json`: 14-second, 24-fps new animation scene reusing the v0.5 sunset setting and hand-directed camera/movement.
- `tests/test_pose_atlas_v06.py`: actual alpha-atlas production, determinism, pose timing, asset overwriting protection, hand metadata and legacy 0.1–0.5 project compatibility.
- `docs/WHOLE_POSE_ART_V06.md` and README: full authoring and Linux Mint/Ubuntu instructions.

A separate original six-pose watercolor/stop-motion image reference has also been produced in the conversation and used in a **local visual concept film**, which shows markedly more coherent human proportions than the previous rectangular limb puppets. The local concept is not falsely presented as GitHub CI output. A real artist may place that or another properly registered image sheet at `examples/assets/pose_courier.png` to replace the technical fallback.

## Art direction and open limitations

The whole-pose option fixes the visual continuity of **individual still poses**, not the timing between poses. The film still uses abrupt cel changes without drawn in-betweens; users should provide additional poses at contact/anticipation beats for a polished 12–24 fps experience. The engine does not invent unseen anatomy, morph two drawings, or synchronize facial phonemes from audio. Hand attachment in pose mode requires an explicit per-pose anchor. The skeletal IK variant remains available where continuous actual limb movement matters.

The most valuable future work would be true hand-painted 8–16-pose cycles, an artist/editor input workflow for anchor registration, and a shot-aware motion-quality acceptance suite. Keep this branch as a draft until its actual GitHub-rendered example is visually inspected and all tests pass.

Do not merge to main or modify earlier branches automatically.
