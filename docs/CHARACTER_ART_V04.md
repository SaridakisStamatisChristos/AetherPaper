# AetherPaper v0.4 — Layered Character Animation

Development branch: feature/character-art-v0.4; based on feature/visual-quality-v0.3. Main is unchanged.

## Scope

v0.4 adds an original, reproducible cutout artkit of 20 separate transparent PNG assets; 14 articulating named bones; real lateral shoulder/hip offsets; foot and hand IK; cloth/hair sway; facial expression and speaking-mouth image variants; and hand-aligned physical prop carrying.

The built-in sample PNGs are generated by original Pillow drawing source. They are useful for exercising the full replaceable-art pipeline, not a claim of professional illustration quality. Users can replace them with their own painted assets without altering the timeline or renderer.

## Linux Mint / Ubuntu installation

    sudo apt update
    sudo apt install -y git python3 python3-venv python3-pip ffmpeg espeak-ng
    git clone https://github.com/SaridakisStamatisChristos/AetherPaper.git
    cd AetherPaper
    git switch feature/character-art-v0.4
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -e '.[dev]'
    pytest -q

## Generate the real artwork and video

    aetherpaper artkit --out examples/assets/atelier_courier
    aetherpaper validate examples/last_light_v04.json
    aetherpaper manifest examples/last_light_v04.json > artkit_manifest.json
    aetherpaper render examples/last_light_v04.json --out output/last_light_v04.mp4
    aetherpaper qa output/last_light_v04.mp4 --frames-dir output/qa_v04

For a smaller preview:

    aetherpaper render examples/last_light_v04.json --width 640 --height 360 --fps 24 --out output/preview_v04.mp4
    aetherpaper snapshot examples/last_light_v04.json --at 5.9 --width 960 --height 540 --out output/preview_still.png

The authored acceptance script is 11 seconds at 24fps with optional 2x supersampling. It depicts a courier entering a moonlit atelier, reaching and picking up a lantern, carrying it, placing it, then speaking.

## Character asset contract

Each body part is independently paintable as a transparent RGBA PNG. The artwork points along its local positive X axis. The JSON part's pivot [0,0.5] attaches the center of the left edge of that PNG to the start of a named bone. Part scale affects the painted layer, not bone length, and z determines depth order.

The 20 separate PNGs include coat/torso, rear cape, independently articulated thighs/shins/boots, four separate arm sections with illustrated hands, hair locks, scarf, face variants (neutral/happy/sad/surprised), and open/closed mouth overlays.

New v0.4 canonical bone naming:

| Upper bone | Lower bone | Function |
|---|---|---|
| arm_l | forearm_l | left arm IK |
| arm_r | forearm_r | right arm IK and prop contact |
| thigh_l | shin_l | left foot IK |
| thigh_r | shin_r | right foot IK |

A bone may declare offset:[x,y], interpreted in actor-scaled screen-space units. Left/right shoulders and hips no longer share one centerline. The positional IK solver uses the actual link lengths and clamps targets beyond reach. Direct pose actions to a limb's bone angles override its procedural IK while active.

Sprite parts may declare expression:neutral/happy/sad/surprised and mouth_state:open/closed. These select the visible PNG based on the character's action and timed speech mouth cues, rather than drawing a face over an unrelated image.

For a pickup action, optional hand_to:[x,y] directs the hand to the prop. The same solved right-forearm endpoint is supplied to the prop state calculator while held; place actions move the hand to the drop-off target before releasing it. This prevents prop and artwork attachment coordinates drifting apart.

Build the artwork once, then modify the PNGs in any image editor. The artkit generator refuses to replace files whose bytes differ from the reproducible original, preventing unintentional loss of artist edits. The assets are rooted in the local project directory and checked before rendering for missing/escaping paths, sizes and SHA-256 checksums.

## Preserved architecture

Older 0.1/0.2/0.3 JSON scenes still load and remain on their respective development branches. Rendering requires no AI model, API subscription, network connection or browser. The offline engine uses Python, Pillow and FFmpeg. No artist asset or upstream licensed code is downloaded.

## Limits

This is layered rigid-cutout animation: not weighted skinning, motion capture, deformable meshes, live character generation, automated photo segmentation or scene-independent realistic contact physics. Although the sample art is more complex than the previous geometric puppet, professional visual quality still needs commissioned/artist-created assets, staging and human review of the rendered film.

Do not promote this draft branch to main automatically. Require successful unit/integration tests, decoded actual MP4 and manual frame inspection.
